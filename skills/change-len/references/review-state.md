# レビューの保存と再レビュー

## コメントを残す

保存ボタンで確定したコメント、対象の元の版・内容、明示したレビュー済み版をブラウザの localStorage に自動保存する。未保存・取消・空欄は記録しない。保存できない場合は、その旨と JSON 保存の案内を表示する。自動保存はブラウザ・ローカルファイルの扱いに依存するため、別のファイル・場所・ブラウザへの移動や配布には JSON を使う。

「コメントの保存・復元」から JSON を保存する。ダウンロードを利用できない環境でも、表示した JSON 全文を選択してファイルへ保存できる。復元は JSON ファイルの選択、または JSON の貼付けで行う。保存済み記録へ追加し、同一コメントの重複は除く。本文・対象・レビュー済み版が競合する復元は拒否し、既存記録を維持する。競合時は両方の JSON を保持し、必要な本文を照合して現在の対象に入力する。

同じ保存先の自動保存があれば、HTML に埋め込んだ初期記録より優先する。HTML 自体を書き換える機能ではない。配布用の HTML に記録を含めるには、下の生成オプションを使う。

## 再生成の入力

同じレビューを追う Report に `reviewKey` を設定する。リポジトリとレビューを区別する安定した識別子を使う。例は `github.com/example/repo#pr:42`。ローカルだけならリポジトリの絶対パスとレビューの識別子を組にする。再生成時は保存 JSON 内の値を引き継ぎ、別のリポジトリ・PR に使い回さない。

同じ論理対象の ID は再生成でも維持する。ID の一致に加え、内容・画面の階層・ファイル・コードの前後・行位置・対応する参照を照合する。関連する出典の内容、確認根拠の状態・方法・条件・結果も比較し、同じ参照 ID でも内容が変われば「確認待ち」にする。変更や移動は「確認待ち」、対象 ID が消えた場合は「対象削除・未収録」とし、同名の別 ID を推測して結び付けない。`reviewKey` がない古い Report の同一版は復元できるが、再生成版への自動引継ぎは確認待ちとなる。

「引継ぎの確認待ち」で元の版・内容と今回の対象を読み、同じ対象なら明示ボタンで引き継ぐ。対象が消えた場合は元の記録を保持し、依頼文にも確認待ちとして含める。引継ぎ後の依頼文にも、最初にコメントした版・対象の内容を残す。

## 前回レビューからの変更

1. HTML の「この版をレビュー済みにする」で、人間が確認した版を明示する。コメント保存やコピーだけでは基準を進めない。
2. 「コメントの保存・復元」で `change-len-review.json` を保存する。
3. 修正後の Report を作成する。同じ `reviewKey` と対象 ID を維持し、コード・根拠・今回の `revision.head` は実際の修正版から採る。PR の初期比較元 `revision.base` はそのまま記録する。
4. 保存 JSON と対象リポジトリを指定して生成する。

```sh
/path/to/change-len/scripts/render.sh /path/to/new-report.json /path/to/review.html \
  --review-state /path/to/change-len-review.json --repo /path/to/repository
```

生成コードが `git diff --no-ext-diff --no-textconv --find-renames --unified=3 <レビュー済みhead> <今回head> --` を取得して HTML に保存する。未取得のコミット・不正な入力・レビュー識別子の不一致で失敗した場合は、既存 HTML を上書きしない。レビュー済み版がまだない JSON でもコメントを埋め込める。

「前回からの変更」はこの Git 差分を表示する。説明・要件は今回の Report から変化した対象や関連する変更を抜粋し、全体像では同じ説明を薄く表示する。初期比較元のコードの前後は、この表示で混在させない。削除・未収録の対象も残し、「今回の変更すべて」で元の文脈へ戻れる。関連コードへ移動すると全変更へ戻る。

Git の両コミットが不明な差分入力では、正確な前回比較を用意できない。初回、比較データのない HTML、記録と比較元が異なる HTML ではボタンを無効にして理由を表示する。今回の head とレビュー済み head が同じなら、差分なしと示す。

## 保存 JSON v1

型は `scripts/review-state.ts` の `ReviewState`。`version: 1`、元の Report の `reports`、`comments`、任意の `reviewed: {snapshot}` を保存する。各コメントは `{id, body, origin: {snapshot, targetId}, binding: {snapshot, targetId}}`。`snapshot` は `reports` の添字。`origin` は最初の版・対象、`binding` は明示確認した引継ぎ先を指す。

Report の全体を保存するため、元のコード・要件・出典・確認根拠も復元できる。外部サービス・AI は呼ばない。JSON にはその内容とレビューコメントが含まれるため、配布するときは共有してよい内容か確認する。
