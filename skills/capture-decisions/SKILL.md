# 決定を残す

後から同じ判断を再現できるよう、決まったことと決まっていないことを残す。

1. 項目ごとに、内容、背景や理由、適用条件、期待結果、決定状態と根拠を残す。本人が述べた理由とAIが推測した理由を区別し、情報がない欄を捏造しない。
2. 「必須／希望」「通常／例外」「含む／含まない」、否定条件、優先順位を要約で落とさない。重要な具体例、前提、依存関係は対応する項目へ結びつける。
3. 状態を、合意済み、暫定、未定、外部確認待ち、委任、不要、未質問に分ける。AIの提案・推測はその旨を明記した未確認の候補として扱う。
4. 合意には本人の回答や確認を根拠として添える。暫定には見直し条件、委任には範囲と判断基準、外部確認待ちには確認方法と完了への影響を残す。分からなければ不明と記録する。
5. 回答がないことや広い「はい」から、個別の条件まで合意を推測しない。包括的な承認があれば、その承認対象として明示された範囲だけに適用する。
6. 変更時は現在の決定を明確にし、置き換えられた内容と理由、再確認が必要な関連項目を残す。矛盾した発言は、本人が変更と明示するまで黙って上書きしない。

項目数と複雑さに応じた短い一覧や表で返す。既存の記録先が指定されていれば同じ記録を更新し、なければ会話内に示す。完全な会話ログを複製せず、重要な根拠を発言や資料へたどれる形で残す。
