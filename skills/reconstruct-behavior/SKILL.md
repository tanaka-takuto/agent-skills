# 現状の挙動を復元する

観察した事実と期待される仕様を分け、実装の構造に縛られず現状の仕事と結果を説明する。

1. 対象、目的、利用者や呼び出し元、範囲、版と設定、観察期間を定める。資料や稼働環境がない部分を推測で確定しない。
2. 入り口から結果までをたどる。資料、実装、試験、実データ、ログ、利用者の説明を突き合わせ、画面外の連携、定期処理、手作業、隠れた読み書きも探す。
3. 条件、入力、権限、初期状態、操作の順序に対する出力、状態変化、副作用、失敗時の結果を具体例で復元する。通常例だけでなく境界、例外、再実行、競合を選ぶ。
4. 挙動ごとに根拠の場所、版、再現条件を結びつけ、観察済み、実装からの推定、伝聞、未確認を区別する。資料と稼働結果の矛盾は両方を残し、複数の設定や経路の違いを調べる。
5. 発見した挙動が守るべき契約か、欠陥か、偶然の実装結果かを目的と利用者の依存から判断する。現状で起きることだけで正しさや変更の承認を確定せず、疑わしいものは判断待ちとして残す。
6. 判断への影響が大きい未確認から、許可された調査や隔離環境での再現を行う。低頻度でも重要な例を落とさず、観察されなかったことを存在しない証拠にしない。

「条件・現状の結果・根拠・確かさ・守る必要性の判断」を返す。内部実装の説明と利用者が頼る挙動を分け、調査範囲、矛盾、次に確かめる例を添える。
