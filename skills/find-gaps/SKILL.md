# 不明点を見つける

同じ情報から異なる判断が生まれる箇所と、判断に必要なのに欠けている情報を見つける。

1. 対象、目的、現在の理解、確認したい範囲を読み取る。記述がないことを「不要」や「任せる」と解釈しない。
2. 曖昧な用語、省略された条件、互いに両立しない期待、根拠のない前提を探す。複数の解釈がある場合は、それぞれで結論がどう変わるかを示す。
3. 呼び出し元が指定した観点を使う。指定がなければ、その仕事の関係者、開始から終了までの流れ、境界、失敗や変更の場面から観点を選び、深掘りしていない別の領域も点検する。
4. 結論への影響が大きく、不確実なものを優先する。実行者の裁量で安全に決められる細部は、重要な不足と区別する。
5. 各観点を、根拠を伴う確認済み、未確認、理由を伴う対象外に分ける。質問済みでも答えが得られていなければ未確認とする。
6. 解消方法を、本人への質問、資料確認、観察や試作、関係者への確認に分ける。質問だけでは確かめられないことを質問で埋めない。

重要な不明点を「不明点・判断への影響・次の確認方法」の形で返し、点検した範囲と未確認の観点を添える。矛盾を勝手に解消せず、新しく見つからなかった場合も点検範囲を超えて「漏れなし」と断言しない。
