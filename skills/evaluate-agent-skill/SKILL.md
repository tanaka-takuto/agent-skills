# Agent Skillの効果を確かめる

対象の依頼・モデル・実行環境で、Skillが何を改善し、どの負担や失敗を増やすかを確かめる。形式検査や文章レビューだけでは有効性を判定しない。

## 進め方

1. 評価対象のSkillと版、想定する利用者・依頼・実行環境、今回決めることを特定する。Skillが補う不足と期待する変化を仮説にする。検証の設計、許可された実行、既存記録の評価のどこまでが依頼範囲かを引き継ぐ。
2. 比較を選ぶ。導入ならSkillなし／あり、改訂なら現行版／候補版を基本にし、両方が必要なら理由を示す。対象以外のSkill、モデル、道具、権限、入力と初期状態をそろえる。パッケージ全体か手順だけか、発動の判断か読み込んだ後の効果かを区別する。
3. 代表的な依頼、紛らわしい非対象、既知の失敗や境界から、判断を変える例を選ぶ。期待結果と必須制約、成果物や実状態を確認する判定方法、追加負担の許容を結果を見る前に定める。Skillの見出しや定型文を再現しただけで合格にしない。
4. 実行・記録を扱う場合は[比較の実施と記録](references/evaluation-guide.md)の該当箇所を読む。隔離した初期状態と新しい会話を使い、先の解答や修正を次の条件へ混ぜない。評価対象が扱う実データや外部操作は試験用に置き換える。既存の許可・予算・停止条件内で実行し、手段がなければ計画として返す。評価の依頼だけで本番更新や追加の有料実行を許可済みにしない。
5. 条件別の実行結果、成果物、検証結果、所要時間、費用、人の確認・修正負担を対応づける。試行の揺れに応じて予算内で繰り返し、失敗・上限到達・未完了も残す。既存記録では比較条件と証拠の出所を確認し、欠測や異なるモデルの結果を同条件として集計しない。
6. 例ごとの改善・回帰と負担を比較し、どの手順や資源が結果を変えたか調べる。必要なら要素を一つずつ外して確かめる。必須制約の違反を平均点で相殺せず、成功例だけの選択や結果に合わせた基準の緩和を避ける。少数試行や差未検出を、普遍的な有効性・無効性の証明にしない。
7. 確認した条件に限って、維持、修正、適用範囲の限定、統合・廃止、追加検証を推奨する。役割の代替と失われる機能も確認し、効果不明だけで廃止を決めない。モデル・道具・Skillの更新時に再評価する例を残す。評価の依頼だけで対象Skillを変更・削除しない。

## 返すもの

比較した版・構成・入力、事前の判定基準、例ごとの結果と証拠、追加負担、推奨と適用条件、未検証と次の確認を返す。既存の記録先があれば更新し、なければ依頼に適した形で提示する。

「計画のみ」「例題の点検」「比較を実行済み」「既存記録の評価」を区別する。比較不能な条件や欠測はそのまま示し、実行していない試行、時間、費用を補わない。資料に基づく評価を独立した再実行と呼ばない。

単なる文章・形式のレビューや整形に、比較実験を自動で追加しない。実際の発動を試していなければ発動精度は未検証とし、強制的に読み込ませた結果と分ける。
