# 要望を詰める

今回の範囲と前提で、本人の意図を実行者が再現できる状態を作る。

## 共通Skill

利用可能なSkill一覧から必要な同名SkillのSKILL.mdを読み、その指示を適用する。同じ処理で会話と記録を共有し、固定順序ではなく不足に応じて使い分ける。

| 必要な仕事       | Skill                                                    |
| ---------------- | -------------------------------------------------------- |
| 意図を引き出す   | [elicit-intent](../elicit-intent/SKILL.md)               |
| 不明点を見つける | [find-gaps](../find-gaps/SKILL.md)                       |
| 理解を照合する   | [verify-understanding](../verify-understanding/SKILL.md) |
| 決定を残す       | [capture-decisions](../capture-decisions/SKILL.md)       |

一覧で見つからなければ、上表の相対パスから同じ配置にあるSkillを読む。見つからなければ依存不足を明示し、その処理を実施済みと扱わない。

## 進め方

1. 既知の要望を拾い、目的、今回の範囲、何を決めれば次へ進めるかを整理する。推測だけで整理を確定せず、重要な不明点から質問する。
2. 要望の点検観点として、目的と成功、人と立場、範囲と境界、利用場面、入出力、判断と例外、品質と体験、運用と連携から必要なものを選ぶ。案件固有の観点を加え、適用しないものは理由を残す。
3. 共通Skillで不足を発見し、意図を引き出し、重要な解釈を照合して、決定を記録する。回答で決定が変わったら、関連する要望や具体例を再確認する。
4. 質問で進まない事項は、必要な情報や検証方法を明確にして外部確認待ちにする。「任せる」は判断範囲を残し、設計者へ委ねた細部を延々と質問しない。
5. 重要な不明点が解消したら、決定、適用条件、具体例、対象外、委任、未解決事項をまとめ、本人が自分の要望として確認できる形で提示する。

## 完了条件

次の条件を満たしたら、今回の範囲で「認識合わせ完了」とする。

- 目的、成功条件、範囲と重要な制約が明確である。
- 重要な用語、利用場面、境界や例外の判断が照合され、矛盾の扱いが決まっている。
- 点検観点に未質問の重要事項がなく、実行に必要な重要事項が合意済み、または範囲と基準を伴って委任されている。
- 残る暫定事項や未解決事項に、扱い、確認方法、実行への影響が記録されている。
- 最終的な整理結果を本人が確認している。確認していない関係者の合意は含めない。

要望の妥当性を確かめる外部検証だけが残るなら「認識合わせ完了・外部検証待ち」とする。実行内容を変える重要事項が残るなら完了としない。途中で終了を求められたら、現在の決定と未解決事項を渡して終了する。確認した範囲を超えて「完全一致・漏れなし」と保証しない。
