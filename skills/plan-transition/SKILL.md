# 切替を計画する

開始と完成だけでなく、途中のどの状態でも仕事と情報が成立する道筋を作る。

1. 現状、目標、期限、許容できる中断や損失、対象と依存、利用者、制約を読み取る。不可逆な変更と先に確かめる仮定を特定し、未指定の許容値を勝手に決めない。
2. 依存と一貫性を保てる切替単位を選び、段階とその間の状態を示す。一括と段階的な切替の負担を比べ、分割が責任の衝突や長期の共存を増やす場合も考慮する。
3. 各状態で、入口、提供する機能、読み取り元、更新の所有者、正本、同期方向、権限、進行中の仕事を定める。複数の更新者が必要なら競合、遅延、重複、失敗と再実行を制御する契約を示す。
4. 各段階の開始条件、準備、作業順、担当、観測、完了条件、中止条件を証拠に結びつける。期限だけで進めず、共存中に現状が変わった場合の計画と基準の更新方法を定める。
5. 失敗時に何をどこまで戻せるかを状態ごとに示す。入口や実装を戻すことと情報を戻すことを区別し、切替後に受け付けた仕事や更新を失わない復旧、戻せない場合の前進修復を用意する。
6. 小さな試行やリハーサルで進行条件と復旧を確かめる。旧方式を止める条件、残る利用者や依存、未完了の仕事、記録の保持、一時的な仕組みの撤去と担当まで含める。

段階ごとの状態、責任、進行と停止の条件、復旧方法を返す。提案と検証済みを分け、戻せる期限や限界、未確認の担当や条件、次に行う小さな試行を明記する。
