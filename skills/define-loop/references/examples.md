# 入力と出力の例

以下は架空の入力に本Skillの手順を手動で適用した指示書と境界の点検である。記載する環境、権限、予算、検証器は例の前提であり、実際にその作業や無人運転を実施した証拠ではない。数値や保存先を共通の既定値にしない。

## 完了条件がある不具合修正

### 入力の前提

- 採用済みの `profile-acceptance@v2` に、AC-1「名前を変更して保存後、新しい読込でも変更後の値が表示される」、AC-2「空の名前は拒否され、保存済みの値は変わらない」がある。
- 終点はローカルの修正と検証。既存の未コミット変更を保護する。公開やマージは依頼範囲に含まない。
- 専用の検証環境で編集、試験用データの更新、ブラウザ操作が許可されている。AC-1/2を操作して保存状態を読める検証器は、合格・不合格・境界例で確認済み。
- 所有者は「準備と検証を含む20分、修正候補は3回まで。無人で予算を追加しない」を指定した。制御層が時刻と候補回数を計測・制限でき、専用の状態保存領域がある。

### 作成した指示書

```text
ループ実行指示書: profile-fix@v1
状態: 指示書作成済み。環境の能力と検証器は入力前提として確認済み。
目的・終点: profile-acceptance@v2 の AC-1/2 をローカルの最終成果物で満たし、証拠を返す。
範囲: プロフィールの保存と入力検証に必要な変更。既存の未コミット変更は保護する。
不変条件: 保存済みデータを不正に変えない。完了条件や検証基準を無断で緩めない。
基準: profile-acceptance@v2 の AC-1/2。実行時に参照を確認し、版を記録する。
起動・寿命: 一回の目標指向の実行。既存の保存状態と再現結果から開始する。
権限: 専用環境の編集・試験用データ・ブラウザ操作。公開やマージは範囲外。

検証: AC-1 は名前を保存して新しい読込で表示と保存状態を確認する。
      AC-2 は空入力を送信し、拒否と元の保存値の維持を確認する。
      各判定に最終成果物の版、環境、入力、操作、観測結果、証拠参照を付ける。
      実行者の説明やCIだけでは、これらの結果を合格にしない。
      受け入れ基準は実行者の編集対象外。試験の正当な追加は許可範囲で行い再検証する。

各回: 最新状態と実物を照合 → 未達条件に関する仮説を一つ選ぶ → 小さく修正
      → 結果・副作用を観測 → AC-1/2と影響する回帰を検証 → 判定と次の一手を保存。
初回: 条件・権限・検証器へのアクセスと、変更前の再現結果を確認する。
完了: 同じ最終版でAC-1/2と不変条件が必要な証拠を伴って成立する。
続行: 残予算があり、新しい観測が次の修正仮説を支える。
      仮説の棄却も根拠にできるが、同じ説明を繰り返すだけでは続行しない。
停滞: 同じ再現入力・失敗・修正方針が2回続き、新しい情報がないなら引き継ぐ。
待ち・検証不能: 必要な判断・権限・観測手段を残し、合格に置き換えない。
失敗・中止: 回復不能、データの不変条件違反、所有者による中止なら追加実行を止める。

予算: 開始から準備・検証を含む20分、修正候補3回のいずれかに先に達した時点で止める。
      制御層で計測・強制し、再開でも使用量を引き継ぐ。自動追加しない。
      上限内の最後の候補ですでに完了の証拠がそろえば完了として返す。
      未達なら上限到達と残作業を返す。期限後に新しい試行を始めない。
状態: 専用領域に条件・成果物の版、AC別の判定と証拠、試した仮説、操作と結果、
      消費予算、未決、次の一手、停止理由を保存する。
再開: 実物と記録を照合し、成果物が変わった場合は影響する検証をやり直す。
      保存操作の前に操作ID・対象・意図を記録する。応答が不明なら保存値を照合してから判断する。
復旧: 自分の変更と試験用データだけを既知の正常状態へ戻す。既存の作業を巻き戻さない。
引渡し: 成果物の版、AC別の実行結果と証拠、残作業、停止理由を返す。
未決: 入力前提が実際の環境で成立しなければ該当分岐を止め、不足を返す。
```

### 判断をたどった結果

| 観測                                                       | 選ぶ判断                                                             |
| ---------------------------------------------------------- | -------------------------------------------------------------------- |
| CIは成功したが、新しい読込で元の名前に戻る                 | AC-1は未達。新しい原因仮説と残予算があれば続行する。                 |
| ACの合格数は同じだが、保存処理か表示処理かを切り分けられた | 次の行動を変える具体的な情報として続行できる。                       |
| 同じ入力・失敗・方針が規定の窓で繰り返され、情報が増えない | 停滞として、試した内容と必要な判断を引き継ぐ。                       |
| ブラウザ操作が使えず、保存・再読込を観測できない           | 検証不能。APIの応答だけでAC-1を合格にしない。                        |
| 3回目の候補で、上限内に全条件の最終版の証拠がそろった      | 完了。未達で候補回数が尽きた場合は上限到達。                         |
| 保存が成立した後、結果の記録前に中断した                   | 操作IDと保存値を照合し、成立した操作を再送しない。残予算も引き継ぐ。 |

## 継続運転と仕事がない回

入力は「毎朝CIの状態を読み、失敗している対象だけ報告する。読取りと報告書保存は許可済み。修正や外部送信は対象外。日次上限と停止スイッチは実行層にある」という依頼である。

指示書には、起動・観測・報告対象の選択、報告の根拠となるCIの実結果、日次上限の更新時点と停止スイッチ、前回の観測との照合を含める。一回の終点は当日の観測・報告結果の保存、運転全体の終了は所有者による終了や定めた運転期限とする。

失敗対象がない回は「仕事なし」と観測を残して終える。翌日の起動を勝手に消さず、恒久的にCIが健全になったとも扱わない。同じ対象の重複入力は集約し、外部サービスが利用不能ならその回を確認不能として残す。修正ループや外部送信の許可を追加しない。

## 成功条件や検証が不足する依頼

入力は「LPをいい感じになるまで自動で改良して。売上が上がれば成功」という依頼で、基準となる実物、合否の判断者、計測期間・データ・比較条件、実行権限は未確定とする。

`define-completion` で、今回求める変化、対象と終了段階、観測できる条件を整理する。`find-gaps` で、見た目の合否、売上の因果、計測・公開の権限がそれぞれどの判断を妨げるかを分ける。計測方法の成立は `test-assumptions` の確認対象になる。

指示書は下書きとして返し、必要な判断と確認方法を結びつける。文字数・モデルの好み・ファイルの存在で売上達成に置き換えず、万能の予算や反復回数を確定しない。既に委任された独立した調査があればその範囲を示せるが、対象作業や公開をこのSkillから始めない。

## 発動条件の境界

| 依頼                                                             | 本Skillの扱い                                                                           |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 「この完了条件から、エージェントへ渡すループ実行指示書を作って」 | 条件を引き継ぎ、実行・観測・検証・続行と停止・再開を組み立てる。                        |
| 「このループは同じ失敗を繰り返す。停止と再開の指示を見直して」   | 観測窓、根拠、予算、再開条件を確認して指示書を改訂する。                                |
| 「このIssueの受け入れ条件だけ決めたい」                          | `define-completion` を使い、ループ指示や実行を付け足さない。                            |
| 「この不具合を修正して」「Markdownを整形して」                   | 対象作業の手順で扱う。指示書作成を求められていなければ本Skillを発動しない。             |
| 「この指示書で実行を開始して」                                   | 実行環境と既存の権限で扱う。本Skillによる指示書作成と実行開始を同じ達成として扱わない。 |
