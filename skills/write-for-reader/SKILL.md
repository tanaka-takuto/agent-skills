# 読者に合わせて説明を組み立てる

読者が必要な情報を見つけ、関係を理解し、自分の場合の判断や行動に使える説明を作る。読む負担を減らしながら、事実、条件、例外、確度を保つ。

## 進め方

1. 依頼と素材から、読者が知りたいこと、既に知ること、読む場面、使う媒体、指定された形式を読み取る。「理解する」を、理由を説明する、案を選ぶ、条件を探す、操作するといった読後の仕事へ具体化する。既知のことを聞き直さず、内容を変える重要な不足だけ確認する。小さな依頼に読者調査や全体設計を追加しない。
2. 素材にある主張、根拠、主体、対象、数値と単位、条件、例外、未確認事項を拾う。観測、推論、提案、決定を区別し、説明のために理由や担当を創作しない。不明・未定は対象と範囲を保ち、期限の未定から実現の見込みや可否へ広げない。推敲では意味を保ち、内容の変更も依頼されていれば変更部分と根拠を区別する。素材が足りない箇所は調査・確認へ回し、分かる範囲の説明は進める。
3. 読者が使う順に構成する。必要な答えとその成立条件を早く示し、理解に必要な文脈を近くに置く。根拠、仕組み、例、詳しい参照へ必要に応じて進めるようにする。既知の説明や作業経緯を並べて入口を重くせず、重要な例外を詳細へ埋めない。結論や同じ要点を形式ごとに繰り返さない。
4. 伝える関係から表現を選ぶ。因果や経緯は段落、独立項目はリスト、実行順は番号、同じ属性の比較は表、関係や状態の追跡は図を候補にする。図表を使う場合や構成に迷う場合だけ、[表現の選択と点検](references/representation-guide.md)の該当箇所を読む。文章だけで足りる案も残し、図表の数や文の長さを一律に決めない。
5. 読者に必要な前提を補い、主体、参照先、用語をそろえて書く。未知の専門語は必要な箇所で説明し、読者が知る用語を幼い言葉へ置き換えない。文を分けても因果・対比・条件のつながりを保つ。見出しや強調は内容を探す手掛かりにし、すべての段落へ付けない。
6. 原資料と稿を比べ、重要な主張、条件、例外、数値、否定、不確実性が変わっていないか確かめる。短くした結果、結論が強くなったり、読者が関係を推測しなければならなくなったりしていれば直す。固定テンプレートの再現、文字数、自然さの自己採点だけで合格にしない。
7. 図表があれば、ラベルと関係を素材に照合する。指定された描画手段と閲覧環境に従い、実際の幅で文字、折返し、切れ、重なり、たどる順序を確認する。構文確認と実表示、読者の理解を分け、表示を確認できなければ該当図表の未確認を明示する。
8. 重要度に応じて、本文だけから読者の問いへ答えられるか点検する。必要なら別コンテキストのAIを予備の読者にして、抜けた前提や誤読候補を探す。人の確認では、要点の言い換え、条件・例外の探索、未掲載の場面への適用や実行で確かめる。日常の短文に追加評価を一律に要求せず、AIの点検を人間での理解確認とは報告しない。

## 返すものと境界

指定された場所・形式で、完成した文章と必要な図表を返す。編集対象が指定されていればその範囲を守る。長い推敲報告、自己採点表、複数形式の同内容を毎回添えない。必要な内容変更や、利用判断を変える未確認があれば短く示す。

誤字・表記修正や機械的な整形だけの依頼には、その作業の手順を使う。翻訳、創作、仕様決定、事実調査の目的を文章改善へ置き換えない。書き方で根拠不足を埋めず、送信・公開・他のファイル編集を依頼なしに追加しない。

改善の評価を求められた場合は、[調査根拠と評価](references/research-and-evaluation.md)を読む。読み始めやすさ、情報探索、理解、利用、意味保持を分け、確認した範囲で効果を述べる。
