# 表現の選択と点検

文章を図や表に変える前に、その表現が読者のどの作業を減らすかを考える。不要な表現は追加せず、必要な関係や条件は残す。

## 読む目的と構成

| 読者の仕事           | 構成で優先するもの                                           |
| -------------------- | ------------------------------------------------------------ |
| 状況や変更を把握する | 何が変わり、誰にどう影響するか。必要な根拠と未確認。         |
| 案を選ぶ             | 共通の比較軸、判断を分ける条件、代償と不確実性。             |
| 操作する             | 開始条件、操作順、成功の確認、失敗時の扱いと止める条件。     |
| 仕組みを理解する     | 必要な前提、主体と状態、因果、具体例と成立しない例。         |
| 必要な情報を参照する | 探す語と一致する見出し、安定した名称、条件の近くにある例外。 |

これは出力欄の固定テンプレートではない。依頼の情報量に合わせて選び、短い説明に全項目を埋めない。先に答えを示すだけでは意味が分からない場合は、必要な状況や用語を先に置く。

## 段落とリスト

段落は、主張と理由、原因と結果、経緯、対比などをつなぐときに使う。話の関係をリストの並び順だけで推測させない。独立した項目を探すときは箇条書き、実行順があるときは番号付き手順を使う。

見出しには、その場所で何が分かるかを予測できる語を置く。結論を見出しにする場合は、必要な条件や確度を落とさない。参照用の項目名が適する場合もあり、すべてを結論文にしない。太字が多すぎて手掛かりを選べなくなるなら減らす。

## 表

複数の対象を同じ属性で照合する場合に使う。列名と単位をそろえ、未確認は未確認とする。比較できない属性を同じ列へ押し込まず、条件の違いを隠さない。

長い文章のセル、似た内容の列、繰り返す項目名が多い場合は、段落や短いリストも比べる。根拠や例外を脚注へ追いやって主張を強めない。閲覧先の幅で読めるか確認し、横方向の往復が比較の助けより大きければ組み直す。

## 図とMermaid

- 図で答える主な問いを決める。分岐や到達経路ならフロー、複数主体の時間順ならシーケンス、状態変化なら状態遷移、責務・包含・依存なら構成や関係の図を候補にする。
- ノードと線に含める事実を素材へ対応づける。「依存する」「送信する」「次に行う」「原因になる」を曖昧な矢印で混ぜない。分岐には条件、状態遷移には契機を示す。
- 概要と詳細を分ける場合は同じ名前と境界を保つ。分割しても対応付けが難しいなら戻す。線の交差だけでなく、意味のまとまりとたどる方向を点検する。ノード数の万能な上限は置かない。
- Mermaidなどの記法、描画ツール、埋込み先は指定と実行環境に合わせる。最新版の描画成功だけで、実際の閲覧先で表示できたとしない。図の制作は利用環境の図作成手順に従う。
- 実表示で文字、ラベル、折返し、重なり、拡大時の読み取りを確認する。対応する環境では `accTitle`・`accDescr` を使い、複雑な図には重要な関係のテキスト代替も用意する。本文を丸ごと図と文章の両方へ再掲しない。

表や図を取り除いた版でも同じ問いへ正しく答えられるなら、追加する読み取り・制作・保守の負担が必要か見直す。描画成功、実表示の確認、人が理解できることは別々に判定する。

## 意味を守る点検例

素材が「送信結果が不明なら再送せず、読戻して確認する」と定める場合、「タイムアウトしたら再送する」への短縮は不合格。否定、条件、操作順が変わっている。「結果不明なら読戻す。確認前には再送しない」なら、同じ条件を保つ候補になる。

素材が「試行したが原因は未特定」としか述べていない場合、流暢さのために「原因はキャッシュだった」と補わない。観測結果を説明し、原因を確かめるために必要な情報を分ける。

「復旧期限は未定」を「復旧見込みは立っていない」へ広げない。日付の未定と復旧の見込みは同じ情報ではない。「費用は未見積」から予算不足を、「担当者は未定」から対応不能を補う場合も、同じように元の主張の範囲を点検する。
