# Agent Skill の作成

1. 依頼から対象の作業、使う場面、想定環境、完了条件を特定する。既定の実行で欠ける判断・手順・資料・道具と、それを補うことで期待する変化を明らかにする。既存Skillの再利用、小さな改訂、スクリプトや既存資料で扱う案も比較し、新設する理由を示す。紛らわしい非対象の依頼があれば境界も決める。
2. 保存先の指定がなければ、このリポジトリの `skills/<name>/SKILL.md` に置く。`name` をディレクトリ名と一致させ、`description` に仕事と使用条件を簡潔に書く。
3. `SKILL.md` には不足を補い、結果を変える判断、手順、検証方法だけを書く。依頼より固定テンプレートを優先させず、一般論や既存資料の複製を増やさない。[リポジトリの上限](../../../.githook/README.md#skillmd-の長さ)は全体500行・8,000文字・1行400文字で、上限を埋めることを目指さない。詳細資料は必要な場合だけ `references/` に、繰り返す決定的な処理は必要な場合だけ `scripts/` に置く。
4. リポジトリルートで、固定バージョンの Prettier を使って作成・変更した `SKILL.md` と参照資料をフォーマットする。初回は `npm ci`、個別のファイルは `npm exec -- prettier --write <対象パス...>`、全 Skill は `npm run format` を使う。設定は `.prettierrc.json` に従う。
5. [Agent Skills 仕様](https://agentskills.io/specification)に照らして frontmatter と参照先を検証する。`npm run check:skill-names` と `npm run check:skill-size`、`npm exec -- prettier --check <対象パス...>` も実行する。実際に使う依頼と、使うべきでない近い依頼で発動条件を確認する。
6. 重要な手順を新設・変更した場合は、[evaluate-agent-skill](../../../skills/evaluate-agent-skill/SKILL.md)で効果を確かめる。利用できる手段と予算で比較し、形式検査、例題の点検、実際の比較結果を区別して返す。整形だけの変更に効果比較を一律に要求しない。
7. 統合・廃止は、役割の重複、利用記録、比較結果、代替手段から判断する。効果未検証だけで不要とせず、新設や削除の件数を目標にしない。削除が依頼範囲なら参照元、利用者の入口、残すべき資源を確認して整理し、一覧と依存先も更新する。モデルや道具の変更で役割が変わる手順には見直し条件を残す。

常時適用する規則や機械的な強制には、それぞれリポジトリ指示やフックが適する場合がある。依頼された Skill の目的を保ちつつ、該当する場合は理由を伝える。
